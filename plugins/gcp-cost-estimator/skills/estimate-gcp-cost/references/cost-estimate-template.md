# Cost Estimate Template Reference

The scaffold for `docs/COST-ESTIMATE.md` and the exact contract for `docs/COST-ESTIMATE.csv`.

**How to use this scaffold**

- Every section has an HTML comment (`<!-- … -->`) stating **what it must contain**, **where the content comes from** (code-inferred vs owner input), and **what "done" looks like**. The comments are guidance — remove them once the section is complete.
- Fill everything the code proves (with `file:line`). Mark everything the code cannot settle `⚠️` and close it in the interview (SKILL Phase 3). Never invent a quantity to make a row look finished.
- Every SKU appears **exactly once** in the summary table, in **catalog order** (the order of `components[]` in `data/cost-components.json`). A SKU that does not run in an environment gets quantity **0** with an `N/A — <reason>` note — never a blank.
- **Show the arithmetic.** Each per-service line states the formula with the real numbers substituted, so a reviewer can check every figure.
- **Quantities only.** No prices, rates, or currency anywhere in either file. Finance prices the quantities.

The scaffold is wrapped in a four-backtick ` ````markdown ` fence so its inner tables/code copy cleanly — copy everything between the fences into `docs/COST-ESTIMATE.md`.

## CSV contract — `docs/COST-ESTIMATE.csv`

Write a second file, `docs/COST-ESTIMATE.csv`, that finance pastes into their pricing sheet. Rules:

- **Exact header row**, verbatim:
  ```
  "Service","Cost Component","Unit","Staging Monthly Qty","Production Monthly Qty","Formula","Assumptions"
  ```
- **One row per catalog SKU, in catalog order** — 22 rows.
- **String cells** (`Service`, `Cost Component`, `Unit`, `Formula`, `Assumptions`) are double-quoted; escape an embedded `"` by doubling it (`""`). The `Cost Component` value is the **verbatim** `skuDescription`.
- **Quantity cells** (`Staging Monthly Qty`, `Production Monthly Qty`) are **bare numbers** — no quotes, `.` decimal separator, **no thousands separators**, no units. A SKU that does not run in an environment is `0`, and its reason leads the `Assumptions` cell (`"N/A — no database; …"`).
- **Formula** cell = the substituted arithmetic (e.g. `"ceil((2*0.5+3*0.25)/0.70)*730 = 2190"`), so the number is auditable.
- **No price/rate/currency columns.** Finance adds pricing columns on their side.
- Encoding **UTF-8**, line endings **LF**, **no BOM**.

**Example rows** (illustrative):
```
"Service","Cost Component","Unit","Staging Monthly Qty","Production Monthly Qty","Formula","Assumptions"
"GKE","Zonal Kubernetes Clusters","cluster-hour",730,0,"1*730 (staging); prod is regional","Staging runs 1 zonal cluster"
"GKE","E2 Custom Instance Core running in Jakarta","vCPU-hour",2190,8760,"ceil(sum(replicas*cpu_req)/0.70)*730","Nodes derived at 0.70 bin-packing"
"Cloud SQL PostgreSQL","Cloud SQL for PostgreSQL: Regional - vCPU in Jakarta","vCPU-hour",0,1460,"2*730 (prod)","N/A staging — no DB in staging overlay; verify HA standby quantity with billing export"
```
